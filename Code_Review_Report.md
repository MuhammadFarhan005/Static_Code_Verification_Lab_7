# Code Review Report: game.cpp

| Line Number | Defect Type | Why It Is Problem | Proposed Fix | Severity |
| :--- | :--- | :--- | :--- | :--- |
| **41–42, 119** | Buffer Overflow / Out-of-Bounds Write | `spawnMonster()` inserts elements into `monsters[monsterCount]` without checking against `MAX_MONSTERS` (5). Adding a 6th monster causes out-of-bounds array access and memory corruption. | Add a check: `if (monsterCount >= MAX_MONSTERS) return;` or use `std::vector<std::unique_ptr<Monster>>`. | High |
| **47** | Assignment in Conditional Expression | `if (monsters[i]->id = id)` uses `=` instead of `==`. This overwrites the monster's `id` and evaluates to `true` for non-zero IDs, always matching the first monster. | Change `monsters[i]->id = id` to `monsters[i]->id == id`. | Critical |
| **54–57, 123** | Null Pointer Dereference & Unsigned Underflow | `findMonster(99)` returns `nullptr`. `m->health` dereferences `nullptr`. Additionally, `m->health - dmg` promotes to `unsigned int`, making `< 0` impossible to evaluate to true. | Add `if (!m) return 0;` and change comparison to `if (m->health <= damage)`. | Critical |
| **64–65** | Off-by-One Loop Bounds / Out-of-Bounds Read | Loop condition `i <= monsterCount` attempts to access `monsters[monsterCount]`, reading past valid initialized array indices (`0` to `monsterCount - 1`). | Change loop condition to `i < monsterCount`. | High |
| **70–73** | Dangling Reference & Null Dereference | `label` is allocated on the stack; returning `std::string&` yields a dangling reference after function exit. Also dereferences `m` without checking for `nullptr`. | Return by value (`std::string`) and ensure `m != nullptr` before constructing the string. | High |
| **77, 80** | Uninitialized Variable & Division by Zero | `double sum;` is uninitialized and accumulates onto garbage memory. If `monsterCount == 0`, `sum / monsterCount` causes division by zero. | Initialize `double sum = 0.0;` and add `if (monsterCount == 0) return 0.0;`. | High |
| **85–86** | Use-After-Free & Double-Free Hazard | `delete m;` deallocates memory before `m->name` is accessed. Furthermore, `m` is not removed from `monsters[]`, leaving a dangling pointer that `~Game()` will delete again. | Save `m->name` prior to deletion, remove pointer from array, adjust `monsterCount`, and set slot to `nullptr`. | Critical |
| **91** | Loss of Precision / Integer Division | `attack * armorPercent / 100` performs integer division before returning `double`, discarding fractional precision. | Cast or use floating-point literal: `(attack * armorPercent) / 100.0`. | Medium |
| **94–99, 128** | Missing Return Path | If `score <= 100` (e.g., `playerRank(50)`), execution falls off the end of a non-void function without returning a value, resulting in undefined behavior. | Add an explicit default return path, e.g., `else return 3;`. | High |
| **102, 105, 109** | Unbounded Input & Mismatched Deallocation | `std::cin >> name` can overflow the 10-character array. `delete name;` uses scalar delete on memory allocated with `new[]` (undefined behavior). | Replace `char*` with `std::string name;` to automate bounds and memory management without `new`/`delete`. | High |
| **121** | Memory Leak | `Monster* bonus = new Monster(...)` allocates memory on the heap that is never released via `delete`. | Delete `bonus` before exiting `main()`, or use stack allocation / `std::unique_ptr`. | Medium |
| **133** | Rule of Three Violation / Shallow Copy | `Game copy = game;` performs a default shallow copy of raw pointers. Destructors of both objects will execute `delete` on the same addresses, triggering a double-free crash. | Implement custom copy constructor and copy assignment operator (or define `Game(const Game&) = delete;`), or use smart pointers. | Critical |
